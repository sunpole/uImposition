# R3 operator-first workspace concepts

Этот каталог содержит design-only интерактивный макет для Issue #71. Он не подключён к production state, solver, PDF или legacy DOM.

Открываемая страница после merge:

```text
https://sunpole.github.io/uImposition/design/r3-concepts/
```

## Управление макетом

В верхней тёмной панели можно переключить:

- концепцию A/B/C;
- desktop 1440/1024;
- mobile 390/360;
- один или пять видов продукции;
- ready/calculating/error state.

Кнопка `Новый пресет` открывает макет компактного локального sheet/press preset editor.

## A — Быстрый производственный стол

### Идея

Один основной рабочий экран:

```text
presets
→ product rows + live summary
→ compact comparison
```

### Сильные стороны

- максимально близок к первоначальному описанию владельца;
- минимальное число переходов;
- пресеты доступны сразу;
- основные параметры заказа и текущий результат видны одновременно;
- хорошо подходит для частых небольших заказов;
- mobile естественно превращается в последовательность `Заказ → Варианты → Схема`.

### Риски

- при большом числе видов вертикальная область становится длинной;
- preview схемы не находится постоянно рядом с вводом;
- требуется аккуратное progressive disclosure для технологических полей.

## B — Разделённый рабочий экран

### Идея

```text
input/product rows | live layout and metrics
                    ↓
              result comparison
```

### Сильные стороны

- оператор сразу видит, как изменение заказа влияет на схему;
- последний корректный результат остаётся рядом с draft input;
- удобно объясняет связь между вводом и производственным результатом;
- selected layout и сравнение не требуют отдельного длинного экрана.

### Риски

- требует ширины; на 1024 px обе части становятся плотными;
- mobile не может быть простым уменьшением desktop и переходит в самостоятельные экраны;
- для 10–20 строк ввода левая колонка может стать тесной.

## C — Таблица оператора

### Идея

Плотная spreadsheet-like таблица продукции и постоянная правая сводка.

### Сильные стороны

- быстрее всего для опытного оператора и большого количества видов;
- клавиатурный ввод и копирование строк масштабируются лучше карточек;
- все основные производственные поля могут быть видимы как колонки;
- summary и варианты всегда доступны справа.

### Риски

- самый высокий порог входа;
- сложнее сделать понятным новому пользователю;
- desktop-таблица принципиально не переносится на mobile;
- избыток колонок может снова создать ощущение перегруженности.

## Рекомендация

Рекомендуемая база — **A: Быстрый производственный стол**, дополненная двумя элементами других направлений:

1. из B — раскрываемая правая/нижняя панель живой схемы выбранного результата;
2. из C — дополнительный `Табличный режим` для заказов с большим количеством видов, но не как единственный интерфейс.

Такой hybrid сохраняет главный быстрый workflow:

```text
быстрый preset
→ короткая строка продукции
→ немедленный live result
→ сравнение по бумаге/forms/cost
```

и не лишает профессионального оператора плотного режима для сложных заказов.

## Обязательные границы будущего R3

- новый entrypoint, не копия `index.html`;
- отдельная чистая CSS-система;
- R2 application state и product-row collection — единственный input contract;
- field error рядом с полем;
- последний valid result сохраняется при ошибочном draft;
- recommendation и operator selection разделены;
- missing price не превращается в ноль;
- mobile реализует самостоятельный flow;
- solver, production formulas и PDF не меняются в UI PR.
