# AGENTS.md — правила работы над uImposition

## Источники истины

1. `docs/TECHNICAL_SPECIFICATION_RU.md` — основной источник требований.
2. `docs/TECHNICAL_SPECIFICATION_EN.md` — профессиональная английская версия.
3. `src/config.js` — источник действующих значений после начала разработки.
4. `data/control-case.json` — контрольный набор.
5. `VERSION.json` — машинный источник текущей версии и статуса.
6. `VERSION.md` — понятное человеку состояние проекта.
7. `CHANGELOG.md` — история изменений по версиям.
8. `docs/VERSIONING.md` — правила версионирования.

## Обязательные правила

- Не начинать крупную реализацию без проверки ТЗ.
- Не менять производственные формулы молча.
- Не добавлять магические числа вне конфигурации.
- Не строить оборот независимо от лица.
- Не принимать вариант с недопечаткой.
- Не считать ручной контрольный вариант доказанным глобальным минимумом.
- Любое изменение русского текста должно быть отражено в профессиональной английской версии.
- Любая новая настройка должна быть добавлена в конфигурацию и справочник.
- После каждого патча запускать соответствующие тесты.
- Не утверждать, что функция готова, пока она не реализована и не проверена.

## Правила версии

- Текущая версия читается сначала из `VERSION.json`.
- `VERSION.md` и `CHANGELOG.md` не должны противоречить `VERSION.json`.
- При изменении версии одновременно обновлять `VERSION.json`, `VERSION.md` и `CHANGELOG.md`.
- После появления версии в интерфейсе синхронно обновлять и её.
- После появления `package.json` синхронно обновлять поле `version`.
- Git-тег и GitHub Release создаются только для зафиксированного релиза.
- Завершённый функциональный этап получает новую версию; незавершённая работа не выдаётся за релиз.

## Предпочтительная технология

- HTML, CSS, JavaScript ES modules;
- без обязательного build step;
- чистые расчётные функции;
- Node built-in test runner или другой минимальный тестовый инструмент;
- GitHub Pages.

## Формат отчёта агента

После задачи сообщить:

1. что изменено;
2. какие файлы затронуты;
3. какие тесты выполнены;
4. какие риски или нерешённые вопросы остались;
5. изменилась ли версия;
6. синхронизированы ли `VERSION.json`, `VERSION.md` и `CHANGELOG.md`.
