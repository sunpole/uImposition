# M7.3 — compact Pareto display alternatives

## Статус

Этот документ описывает функциональный подэтап M7.3 после базовой Pareto-модели.

- опубликованная версия проекта остаётся `0.7.0-alpha.2`;
- код относится к `Unreleased — M7.3 development`;
- подэтап не добавляет пользовательский UI и не является release checkpoint;
- источник истины — `src/pareto-display-set.js` и regression-тесты.

## Задача

Pareto-frontier может содержать больше вариантов, чем оператору удобно сравнивать одновременно. Простое `slice(0, limit)` скрывает технологически важные крайние решения и зависит от текущей сортировки.

Компактный набор должен:

1. всегда показывать текущую рекомендацию;
2. сохранять уникальные крайние решения по обязательным целям;
3. не повторять одно решение, если оно лучше сразу по нескольким целям;
4. заполнять свободные места существенно отличающимися компромиссами;
5. возвращать точные причины включения и дельты;
6. честно сообщать, сколько frontier-вариантов скрыто;
7. не подменять отсутствующую стоимость нулём.

## Порядок отбора

### 1. Рекомендация

Рекомендованный вариант определяется текущим `objectiveOrder` через детерминированное лексикографическое сравнение. Его можно передать явно через `recommendedSolutionId`.

### 2. Обязательные крайние варианты

По умолчанию закрепляются минимумы:

- физической бумаги;
- расчётной стоимости, только если стоимость входит в доступные цели;
- layout-форм;
- цветовых пластин;
- перетиража готовых файлов;
- перетиража печатных пар;
- листопрогонов.

Если одно решение выигрывает несколько категорий, оно включается один раз, а в `extremeObjectiveIds` сохраняются все причины.

### 3. Прозрачное расширение лимита

Если `displayLimit` меньше числа уникальных обязательных решений, модель не скрывает обязательные варианты. Она возвращает:

- `requestedDisplayLimit`;
- `effectiveDisplayLimit`;
- `limitExpandedBy`.

Это делает изменение лимита видимым и проверяемым.

### 4. Разнообразные компромиссы

Оставшиеся места заполняются методом:

`recommended-extrema-maximin-range-distance`

Для каждой доступной цели вычисляется диапазон frontier. Разница двух решений нормализуется по этому диапазону. Расстояние пары равно наибольшей нормализованной разнице по доступным целям.

Для каждого кандидата находится ближайшее уже выбранное решение. Затем выбирается кандидат с максимальным расстоянием до своего ближайшего выбранного решения.

Таким образом, модель выбирает вариант, который добавляет наиболее заметный новый компромисс. Скрытого суммарного score и пользовательских весов нет. При равенстве используется текущий лексикографический `objectiveOrder`.

## Результат

`buildParetoDisplaySet()` возвращает:

- рекомендацию и reference-вариант;
- доступные цели и диапазоны метрик;
- mapping крайних целей на решения;
- уникальный обязательный набор;
- отображаемые entries;
- причины `recommended`, `extreme`, `diverseTradeoff`;
- ближайший выбранный вариант и нормализованное расстояние для diversity-entry;
- преимущества, компромиссы и равные цели относительно reference;
- точные metric deltas;
- количество скрытых frontier-вариантов и их идентификаторы;
- `pricingComparable`.

## Pricing guard

Pareto-метрика считается допустимой только когда её значение является настоящим конечным числом JavaScript.

Следующие значения запрещены для включённой цели:

- `null`;
- `undefined`;
- числовая строка;
- пустая строка;
- `NaN`;
- `Infinity`.

При `pricing incomplete` денежная цель должна быть явно исключена из `objectiveIds` и `objectiveOrder`. Тогда:

- `pricingComparable === false`;
- денежный extreme отсутствует;
- денежные дельты отсутствуют;
- нулевая стоимость не выдумывается.

## Проверки

Regression-набор проверяет:

- рекомендацию и уникальные extrema;
- объединение нескольких extreme-причин у одного решения;
- расширение слишком малого display limit;
- стабильность результата при обратном порядке входных кандидатов;
- structured advantage/tradeoff deltas;
- работу без денежной цели при неполном прайсе;
- запрет coercion `null → 0` и строк → числа;
- неизвестный recommendation/reference;
- недопустимый лимит.

## Что не входит

Этот подэтап не добавляет:

- реальные автоматически сгенерированные M7.3 alternatives из производственного pipeline;
- человекочитаемые RU/EN предложения для карточек;
- отдельный breakdown `бумага / пластины / подготовка форм / итог`;
- UI таблицы вариантов;
- Chromium-сценарий именно для нового UI;
- release news, evidence archive, recovery branch, tag или prerelease `0.7.0-alpha.3`.

Эти пункты выполняются следующими подэтапами до завершения M7.3.
