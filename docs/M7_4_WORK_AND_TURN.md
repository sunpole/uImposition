# M7.4 — свой оборот / work-and-turn

Дата фиксации документа: 2026-07-26.

## Назначение

M7.4 добавляет вторую явно моделируемую duplex-стратегию:

- `separateFrontBackForms` — отдельная форма лица и отдельная форма оборота;
- `workAndTurn` — одна симметричная форма используется для обоих прогонов после горизонтального переворота листа.

Стратегия не реализована как условие внутри DOM-кода. Геометрия общей формы, производственные метрики, runtime и UI разделены на самостоятельные модули.

## Режимы оператора

Поддерживаются три явных режима поиска:

1. `separateOnly` — разрешён только обычный чужой оборот;
2. `compareBoth` — показать и сравнить обе стратегии;
3. `workAndTurnOnly` — разрешён только свой оборот.

Переключение режима фильтрует уже подготовленные и проверенные метрики. Оно не перестраивает геометрию и production report.

## Чистая модель общей формы

`src/work-and-turn-layout.js` строит одну общую форму из половины строк:

- число колонок обязательно чётное;
- в левой половине размещаются страницы лица;
- в зеркальной позиции правой половины размещается парная страница оборота того же файла и той же пары;
- направление парной ячейки проверяется через горизонтальное отражение;
- поддерживается только явно зафиксированный `horizontal` turn axis;
- один plate object имеет `samePlateForBothPasses: true`.

Повреждённая зеркальная пара, неизвестная страница, нечётное число колонок или другой turn axis блокируют результат.

## Независимая проверка готового изделия

Для повторного использования существующей проверенной арифметики общая форма материализуется в канонические `front` и `back` layouts.

Это не означает две физические формы. Materialization нужна только для независимой проверки готовых пар и количества изделий через существующие:

- `createBackLayout`;
- `validateImposition`;
- `buildProductionReport`.

Физическая технология фиксируется отдельно в `runMetrics`:

| Стратегия | frontForms | backForms | forms | press passes |
|---|---:|---:|---:|---:|
| separate front/back | 1 | 1 | 2 | `runLength × 2` |
| work-and-turn | 1 | 0 | 1 | `runLength × 2` |

`production-validation.js` проверяет эти значения по выбранному duplex mode и больше не предполагает безусловные `1 + 1` формы.

## Контрольный кейс M7.4

Фиксированный кейс:

- четыре разных файла: `A`, `B`, `C`, `D`;
- готовый формат A6 `105 × 148 mm`;
- по `2` страницы;
- красочность `1+1`;
- тираж каждого файла `4000`;
- исходный лист `620 × 450 mm`;
- проверенная печатная область `608 × 431 mm`;
- сетка `4 × 4`, поворот изделия `90°`;
- длина тиража формы `1000` листов.

Общая форма:

```text
A·1  B·1  B·2  A·2
C·1  D·1  D·2  C·2
A·1  B·1  B·2  A·2
C·1  D·1  D·2  C·2
```

Проверенный результат:

| Метрика | Чужой оборот | Свой оборот |
|---|---:|---:|
| физические листы | 1000 | 1000 |
| листопрогоны | 2000 | 2000 |
| layout-формы | 2 | 1 |
| цветовые пластины при 1+1 | 2 | 1 |
| недопечатка | 0 | 0 |
| перетираж | 0 | 0 |

Таким образом, свой оборот не заявляет экономию бумаги или прогонов в этом кейсе. Он экономит ровно одну layout-форму и одну цветовую пластину.

## Стоимость

Демонстрационные цены не подставляются автоматически.

При готовом операторском прайсе стоимость считается существующей моделью `production-cost.js`:

- бумага одинакова у обеих стратегий;
- стоимость одной цветовой пластины экономится;
- стоимость подготовки одной layout-формы экономится, если оператор ввёл ненулевую ставку;
- общая денежная экономия равна сумме этих двух компонентов.

Контрольный Chromium-кейс вводит:

- `130 g/m²`;
- `4 BYN/kg`;
- `15 BYN` за цветовую пластину;
- `0 BYN` за подготовку layout-формы.

При этих вводных UI обязан показать экономию `15 BYN`. Эти числа являются evidence-профилем, а не рабочими значениями по умолчанию.

## Runtime и публичное состояние

`src/work-and-turn-runtime.js`:

- подготавливает обе стратегии один раз на текущий pricing state;
- применяет режим оператора без повторной генерации;
- выбирает work-and-turn при сравнении, потому что бумага и прогоны равны, а форм и пластин меньше;
- полностью скрывает денежные значения до готового прайса;
- публикует только очищенные метрики и безопасный plate preview;
- не публикует production reports, raw front/back layouts, pagePairs или halfRows.

Публичное событие: `uimposition:work-and-turn`.

## UI

Основная страница получает компактный RU/EN-блок:

- три режима оператора;
- две карточки стратегий;
- листы, прогоны, layout-формы, пластины, недопечатка и итоговая стоимость;
- точное резюме `1000 / 2000 / 2→1 / 2→1`;
- фактический preview общей формы `4 × 4`;
- обязательное технологическое предупреждение.

Предупреждение принципиально сохраняется: математическая симметрия не заменяет проверку захвата, бокового упора, приводки и допустимости переворота на конкретной печатной машине.

## Проверки

Unit/regression coverage включает:

- правильные зеркальные пары;
- отклонение повреждённой пары;
- materialization через существующий duplex validator;
- независимый production report обеих стратегий;
- точные `1000` листов и `2000` прогонов;
- `2 → 1` формы и пластины;
- нулевую недопечатку и перетираж;
- три режима оператора;
- отсутствие выдуманных денежных значений;
- точную экономию одной пластины и одной подготовки;
- очищенное runtime state;
- отклонение нечётной сетки.

## Граница M7.4

M7.4 доказывает технологическую стратегию и контрольный A6-кейс.

M7.4 не заявляет:

- общий автоматический work-and-turn поиск для произвольного набора заказов;
- поддержку вертикального переворота;
- автоматический выбор захвата или бокового упора;
- автоматическую проверку ограничений конкретной печатной машины;
- экономию бумаги там, где фактические метрики её не подтверждают.

Расширение на произвольные заказы должно использовать это ядро и добавлять отдельные fixtures, а не ослаблять текущую валидацию.
