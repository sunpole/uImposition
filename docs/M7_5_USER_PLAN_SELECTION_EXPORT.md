# M7.5 — выбор и экспорт пользовательского производственного плана

Дата: 2026-07-27.

## Цель

Оператор должен иметь возможность выбрать любой допустимый вариант из lossless-каталога — рекомендуемый, Pareto, доминируемый, дорогой или технологически удобный — и получить производственные материалы именно для своего выбора.

Рекомендация программы не является автоматическим выбором.

## Явный выбор

Новый внутренний runtime хранит:

- текущий полный user plan set;
- выбранный `planId`;
- полный выбранный план только внутри модулей приложения.

После построения каталога выбранного плана нет. Оператор нажимает `Выбрать` на нужной карточке.

Если меняются только цены и план с тем же стабильным ID остаётся доступным, выбор сохраняется и получает пересчитанные метрики. Если новые размеры, заказы или ограничения удалили выбранный план, выбор очищается.

## Публичное состояние

Браузерное событие `uimposition:user-plan-selection` содержит только безопасную сводку:

- ID и подпись;
- family;
- ориентацию и сетку;
- листы, формы, пластины, прогоны и перетираж;
- стоимость и статус прайса;
- признак нулевой недопечатки.

Raw layouts, полный production report, pair contributions и схемы не публикуются в глобальный объект или публичное событие.

## Панель выбранного плана

После явного выбора отображаются:

1. ключевые производственные метрики;
2. фактическая ориентация и сетка;
3. materialized front/back схемы;
4. динамический production report;
5. итоги по файлам;
6. итоги по печатным парам;
7. вклад каждого монтажа;
8. экспорт схем и отчёта в PDF.

Старый renderer контрольного отчёта здесь не используется, потому что в нём были фиксированные тексты и числа контрольного набора. Пользовательский renderer формирует подписи и таблицы только из фактического выбранного отчёта.

## Preview схем

Для сохранения скорости интерфейса показываются первые `8` монтажей выбранного плана.

Если план содержит больше монтажей, интерфейс явно пишет:

- сколько показано;
- сколько существует всего;
- что PDF содержит полный выбранный план.

Ограничение preview не изменяет расчёт, каталог, production report или PDF.

## PDF

### PDF схем

- одна схема на страницу;
- лицо и оборот каждого монтажа идут отдельными страницами;
- A4 как безопасный текущий режим;
- количество страниц равно `число монтажей × 2`;
- имя файла включает ID выбранного плана.

### PDF production report

- создаётся из `selectedPlan.report`;
- не использует контрольный report;
- содержит фактические summary, file totals и pair totals;
- имя файла включает ID выбранного плана.

### Лимит интерактивного экспорта

PDF схем временно ограничен `120` монтажами в одном интерактивном browser-export.

Если план больше:

- выбранный план не удаляется;
- production report остаётся доступным;
- программа показывает явное сообщение;
- PDF не начинает тяжёлое синхронное построение, способное заморозить телефон.

Следующий масштабируемый этап — отдельный worker с прогрессом и отменой.

## Mobile

На ширине около `390 px`:

- кнопка выбора занимает доступную ширину;
- выбранная карточка получает отдельный operator-selected outline;
- сводные метрики идут по две в строке;
- preview и report остаются вертикальными;
- большие таблицы имеют локальную горизонтальную прокрутку;
- export-кнопки располагаются одна под другой.

## Проверяемые инварианты

- recommendation не выбирается автоматически;
- оператор может выбрать любой plan ID;
- выбор сохраняется после пересчёта, если ID ещё существует;
- выбор очищается, если план исчез;
- PDF document model использует именно выбранный план;
- у контрольного пользовательского dedicated-плана `3` монтажа дают `6` страниц схем;
- недопечатка выбранного плана равна нулю;
- публичное событие не содержит raw layouts или report.

## Граница

Эта функция экспортирует выбранный вариант внутри текущей области user uniform planner:

- один общий формат изделия;
- fitting uniform grids `0°/90°`;
- две plan-family;
- отдельные лицевые и оборотные формы;
- общая цветность заказа;
- полные front/back пары.

Она не означает, что уже реализованы:

- mixed-format packing;
- смешанные повороты;
- глобальный перебор всех последовательностей форм;
- общий user-driven work-and-turn;
- индивидуальные параметры каждой строки заказа;
- сохранение проекта;
- расчёт выручки и прибыльности.

## Следующие шаги

1. завершить доступный редактор порядка целей и цен;
2. добавить больше plan-family и ограниченный перебор последовательностей форм;
3. подключить свой оборот к пользовательскому планировщику;
4. расширить модель строки заказа;
5. реализовать mixed-format и mixed-rotation;
6. вынести тяжёлый поиск и PDF в worker;
7. сохранить и переносить выбранный проект.
