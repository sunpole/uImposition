## Цель M6 / M6 goal

Автоматически формировать допустимые лицевые монтажи, назначать им тиражи и находить вариант с минимальным количеством физической бумаги без недопечатки.

Automatically generate valid front-imposition candidates, assign run lengths, and find the minimum-physical-paper solution without underproduction.

## Разделение событийных тиражей

Для кандидата `m`, пары `i`, остатка спроса `R_i` и числа позиций `n_i,m`:

```text
T_first(m)    = min_i ceil(R_i / n_i,m)
T_complete(m) = max_i ceil(R_i / n_i,m)
```

- `T_first` закрывает хотя бы одну активную пару;
- `T_complete` самостоятельно закрывает все активные пары этого кандидата;
- ни одно значение отдельно не доказывает глобальный минимум;
- окончательный вариант допустим только при нулевом остатке всех пар.

## Реализованные слои

### M6.1 — чистая модель кандидата

- `src/imposition-candidate.js`;
- неизменяемое состояние спроса;
- полный кандидат `rows × columns`;
- расчёт `T_first` и `T_complete`;
- применение явного тиража;
- мост к существующему `createFrontLayout`;
- запрет неизвестных пар, повторных блоков, неполного лица и недопустимых тиражей.

Контроль: кандидат №1 даёт `T_first = 1500`, `T_complete = 3500`; четыре ручных тиража сохраняют `3395` листов, недопечатку `0`, перетираж пар `1450`.

### M6.2 — точное ограниченное пространство кандидатов

- `src/candidate-generator.js`;
- генерируются все полные кандидаты с одной или двумя различными парами;
- число позиций каждой пары положительное;
- эквивалентность определяется производственной сигнатурой;
- усечение всегда возвращается явно.

Для 35 пар и вместимости 16:

```text
C(35,1) × C(15,0) + C(35,2) × C(15,1) = 35 + 8925 = 8960
```

Контрольный набор содержит все `8960` кандидатов без усечения.

### M6.3 — конструкция и доказательство минимума бумаги

- `src/paper-minimizer.js`;
- базовые полные тиражи каждой пары;
- упаковка остаточных потребностей в полные 16-позиционные листы;
- не более двух различных пар на кандидат;
- объединение производственно эквивалентных тиражей;
- повторная материализация лица, зеркального оборота и производственного отчёта.

Универсальная нижняя граница:

```text
total required pair quantity = 52870
capacity per physical sheet   = 16
paper lower bound             = ceil(52870 / 16) = 3305
```

Построенный вариант достигает `3305`, поэтому для текущего контрольного набора бумажный минимум доказан глобально:

- бумага: `3305` вместо `3395`;
- экономия: `90` листов;
- недопечатка: `0`;
- перетираж пар: `10` вместо `1450`;
- готовые файлы: перетираж `0`;
- листопрогоны: `6610` вместо `6790`;
- монтажи: `56` вместо `4`;
- layout-формы сторон: `112` вместо `8`.

Это доказанный минимум **бумаги**, но не производственно рекомендуемый компромисс. Минимизация форм и Парето-набор относятся к M7.

## Производственные regression-кейсы

Источник: `data/production-regression-cases.json`.

### 1. A6 альбомный, 32 страницы, 4+4

- готовый размер: `148 × 105`;
- печатная область: `608 × 431`;
- сетка: `4 × 4 = 16` без поворота;
- страницы образуют `16` пар: `1/2 … 31/32`.

### 2. A6 вертикальный, 32 страницы, 4+4

- готовый размер: `105 × 148`;
- лучший поворот: `90°`;
- итоговая ячейка: `148 × 105`;
- сетка: `4 × 4 = 16`;
- без поворота помещается только `5 × 2 = 10`.

### 3. Смешанный двухсторонний монтаж 4+4

На одном лице `608 × 431` проверена ручная раскладка:

```text
верх: 1×A4 landscape (297×210) + 2×A5 portrait (148×210)
низ:  2 ряда × 4×A6 landscape (148×105)
```

Итого: `1 A4 + 2 A5 + 8 A6 = 11` изделий. Использовано `248850 мм²`, свободно `13198 мм²`. Оборот выводится только горизонтальным зеркалированием лица.

Граница: M6 проверяет заданную смешанную раскладку, отсутствие пересечений, границы листа и зеркальный оборот. Автоматический rectangle-packing смешанных форматов ещё не реализован.

### 4. A5, 8 позиций, разные двухстраничные тиражи 4+4

Заказы:

- вид 1: `400`;
- вид 2: `700`;
- вид 3: `4200`.

Сетка A5 `148 × 210`: `4 × 2 = 8`.

```text
total demand = 5300
lower bound  = ceil(5300 / 8) = 663
```

Доказанный результат:

- тиражи трёх монтажей: `50`, `88`, `525`;
- бумага: `663`;
- формы сторон: `6`;
- цветовые пластины при 4+4: `24`;
- листопрогоны: `1326`;
- недопечатка: `0`;
- перетираж: только вид `700 → 704`, то есть `4`.

## 4+4: layout-формы и цветовые пластины

`src/print-specification.js` не позволяет смешивать два разных показателя:

- один двухсторонний монтаж имеет `2` layout-формы сторон;
- один монтаж 4+4 имеет `8` цветовых пластин;
- три монтажа A5 имеют `6` layout-форм и `24` цветовые пластины.

Текущий production report исторически считает layout-формы сторон. Цветовые пластины пока являются отдельной проверяемой метрикой и не подменяют существующее поле `forms`.

## Важная граница 32-страничного изделия

Regression-тест проверяет размеры, ориентацию, вместимость и последовательные пары `1/2 … 31/32`. Настоящий тетрадный/фальцевальный спуск полос с сигнатурной пагинацией пока не реализован и не должен подразумеваться результатом этого теста.
