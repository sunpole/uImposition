# M6 — кандидаты и минимум бумаги / Candidates and paper minimisation

## Статус / Status

Рабочий план ветки `m6/0.6.0-alpha`. Публичная версия остаётся `0.5.0-alpha`, пока автоматический поиск не будет реализован и доказан.

Working plan for `m6/0.6.0-alpha`. The public version remains `0.5.0-alpha` until automatic search is implemented and verified.

## Цель M6 / M6 goal

Автоматически формировать допустимые лицевые монтажи, назначать им тиражи и находить вариант с минимальным количеством физической бумаги без недопечатки.

Automatically generate valid front-imposition candidates, assign run lengths, and find the minimum-physical-paper solution without underproduction.

## Разделение понятий / Required distinction

Для кандидата `m`, пары `i`, остатка спроса `R_i` и числа позиций `n_i,m` существуют два разных тиража:

```text
T_first(m) = min_i ceil(R_i / n_i,m)
T_complete(m) = max_i ceil(R_i / n_i,m)
```

- `T_first` — первый событийный тираж: хотя бы одна активная пара кандидата становится полностью закрыта;
- `T_complete` — самостоятельный завершающий тираж: все активные пары, присутствующие на кандидате, полностью закрыты;
- `T_first` нельзя выдавать за готовое глобальное решение;
- `T_complete` не обязательно оптимален, потому что другие кандидаты могут совместно допечатать те же пары;
- окончательный вариант допустим только при нулевом остатке по всем печатным парам.

`T_first` is the first event at which at least one active pair is satisfied. `T_complete` is the run required for this candidate alone to satisfy every active pair it contains. Neither value by itself proves a global optimum.

## M6.1 — чистая модель кандидата

Добавить DOM-независимый модуль, который:

- нормализует полный лицевой кандидат;
- хранит сетку, поворот, блоки и число позиций каждой пары;
- запрещает неизвестные пары, повторные блоки и неполное лицо;
- создаёт исходное состояние спроса по всем парам;
- рассчитывает `T_first` и `T_complete`;
- применяет явный тираж кандидата к неизменяемому состоянию спроса;
- возвращает остаток, новый перетираж и полностью объяснимые вклады;
- формирует вход для существующего `createFrontLayout` без дублирования логики оборота.

### Граница M6.1

- кандидаты ещё не генерируются автоматически;
- тиражи ещё не выбираются оптимизатором;
- UI и версия не меняются;
- ручные четыре монтажа используются только как контрольная последовательность;
- результат `3395` листов остаётся ориентиром, а не доказанным минимумом.

## M6.2 — генерация кандидатов

После проверки M6.1:

- генерировать полные наборы из `rows × columns` позиций;
- сохранять один непрерывный row-major блок для каждой пары;
- ограничивать комбинаторный рост конфигурацией;
- канонизировать эквивалентные кандидаты;
- не строить оборот на стадии генерации: он по-прежнему выводится из выбранного лица.

## M6.3 — поиск тиражей и решений

- использовать событийные тиражи вместо перебора каждого целого значения;
- применять кандидаты к остаточному спросу;
- отсекать состояния, которые уже используют не меньше бумаги, чем лучший найденный результат;
- мемоизировать канонический остаточный спрос;
- принимать решение только при остатке `0` по всем парам;
- независимо проверять итог существующим производственным отчётом.

## M6.4 — выбор и объяснение

Для каждого допустимого решения показывать:

- физическую бумагу;
- формы и листопрогоны;
- перетираж пар и готовых файлов;
- число монтажей;
- разделённые заказы;
- вклад каждого монтажа;
- сравнение с ручным ориентиром `3395` листов;
- честный статус: найденный лучший вариант или доказанный минимум в пределах явно указанного пространства поиска.

## Приёмка первого патча / First-patch acceptance

- контрольные 35 пар создают неизменяемое состояние спроса;
- кандидат содержит ровно `rows × columns` позиций;
- кандидат №1 даёт `T_first = 1500` и `T_complete = 3500` на исходном спросе;
- явный тираж `1500` кандидата №1 закрывает пары файла 25, но не весь спрос кандидата;
- последовательное применение ручных тиражей `1500`, `1100`, `450`, `345` даёт остаток `0`, бумагу `3395` и перетираж пар `1450`;
- неполный кандидат, неизвестная пара, повторный блок и недопустимый тираж отклоняются;
- новая логика проходит Node built-in tests и не использует DOM.
