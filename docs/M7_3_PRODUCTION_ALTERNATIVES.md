# M7.3 — real production alternatives

## Статус

Этот документ описывает функциональный подэтап M7.3 после Pareto foundation и compact display set.

- опубликованная версия остаётся `0.7.0-alpha.2`;
- код относится к `Unreleased — M7.3 development`;
- пользовательский UI и release checkpoint `0.7.0-alpha.3` ещё не создаются;
- источники истины: реальные production report и paper minimum solution одного заказа.

## Цель

M7 должен сравнивать не иллюстративные объекты, а реально рассчитанные допустимые производственные решения.

Для текущего контрольного заказа уже существуют два независимых результата:

1. ручной контрольный вариант из четырёх валидных монтажей;
2. доказанный минимум физической бумаги из `minimizePhysicalPaper()`.

Новый слой переводит оба результата в одну модель `SolutionMetrics`, проверяет общую денежную базу и только затем строит decision ranking, Pareto-frontier и compact display set.

## Архитектурная граница

Сырые layouts, candidates, planned runs и production reports не входят напрямую в decision/Pareto модель.

Поток данных:

```text
реальные монтажи / paper solution
        ↓
производственная проверка и измерения
        ↓
SolutionMetrics
        ↓
совместимость прайса
        ↓
decision solutions
        ↓
Pareto frontier
        ↓
compact display set
```

Это позволяет будущим способам раскладки подключаться через свой адаптер `→ SolutionMetrics`, не меняя правила сравнения.

## Распределение заказов по монтажам

`src/imposition-distribution.js` выводит три измеримые метрики из реальных файлов, присутствующих на каждом монтаже.

### Разные заказы на одном монтаже

`distinctOrdersPerImposition` — максимальное число уникальных файлов на одном монтаже.

Повтор одного файла в нескольких позициях одного монтажа считается один раз.

### Разделённые заказы

`splitOrders` — число файлов, которые присутствуют более чем на одном монтаже.

### Дополнительные фрагменты

`fragmentedBlocks` — сумма дополнительных появлений файлов после первого:

```text
fragmentedBlocks = Σ max(0, appearances(file) − 1)
```

Для ручного контрольного решения:

- максимум разных файлов на монтаже: `7`;
- разделённые заказы: `2`;
- дополнительные фрагменты: `3`.

Для paper minimum:

- максимум разных файлов на монтаже: `2`;
- разделённые заказы: `19`.

## Нормализация paper minimum

`src/paper-solution-metrics.js` использует только проверенные поля реального `paperSolution`:

- physical sheets;
- imposition count;
- layout forms;
- color plates;
- press passes;
- file and pair overrun;
- file and pair underproduction;
- ordered finished quantity;
- распределение заказов по planned runs;
- optional production cost на общем прайсе.

Недопечатка остаётся жёстким ограничением. Невалидное или неполное paper solution не принимается.

## Совместимость стоимости

Две готовые суммы нельзя сравнивать только потому, что обе являются числами.

`inspectPricingCompatibility()` требует общую базу:

- одна валюта;
- одна база листа;
- одинаковая площадь исходного листа;
- одинаковая плотность;
- одинаковый вес одного листа;
- одинаковая эффективная цена бумаги за кг;
- одинаковая цена цветовой пластины;
- одинаковая цена подготовки layout-формы.

Возможные состояния:

- `ready` — стоимость включается в objective order;
- `incomplete` — стоимость исключается, потому что не все решения имеют готовый прайс;
- `incompatible` — стоимость исключается, потому что база или ставки отличаются.

Неполная или несовместимая стоимость не превращается в `0` и не участвует в Pareto-доминировании.

## Реальный контрольный результат

Один интеграционный тест заново строит:

- page pairs из `data/control-case.json`;
- четыре ручных front/back монтажа из `data/control-layout-m3.json`;
- production report;
- paper minimum solution;
- реальные `SolutionMetrics` обоих решений;
- decision/Pareto/display pipeline.

При общем иллюстративном прайсе `130 г/м²`, `4 BYN/кг`, `15 BYN` за цветовую пластину:

| Метрика | Compact manual | Paper minimum |
|---|---:|---:|
| Физические листы | 3395 | 3305 |
| Монтажи | 4 | 56 |
| Layout-формы | 8 | 112 |
| Цветовые пластины | 32 | 448 |
| Листопрогоны | 6790 | 6610 |
| Перетираж файлов | 930 | 0 |
| Перетираж пар | 1450 | 10 |
| Разделённые заказы | 2 | 19 |
| Стоимость | 972.5466 BYN | 7199.4894 BYN |

Оба решения:

- имеют нулевую недопечатку;
- используют одну исходную геометрию;
- имеют одинаковую измеренную геометрическую compactness для сетки `4×4`:
  `16 × 105 × 148 / (608 × 431) ≈ 0.9488338014`;
- входят в Pareto-frontier.

При `paper first` рекомендация — paper minimum. При переносе `estimatedTotalCost` на первое место рекомендация мгновенно меняется на compact manual без повторной генерации раскладок.

## Что ещё не входит

Этот подэтап не добавляет:

- отдельные RU/EN предложения `преимущество / цена компромисса`;
- component cost deltas по бумаге, пластинам, подготовке форм и итогу;
- подключение alternative set к runtime event/state приложения;
- пользовательскую таблицу или карточки вариантов;
- новый focused Chromium screenshot;
- news/uNews/Telegram, evidence archive, recovery branch, tag или prerelease `0.7.0-alpha.3`.

Следующий безопасный подэтап — pure explanation и component-cost comparison model, затем runtime/UI интеграция.
