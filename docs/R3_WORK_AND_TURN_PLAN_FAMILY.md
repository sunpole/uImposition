# R3 Work-and-turn plan family

Статус: **активный расчётный контракт R3**.

Этот документ фиксирует фактическую область пользовательского расчёта `workAndTurn` после подключения общей формы к lossless-каталогу вариантов и рабочему маршруту `/app/`.

## 1. Что реализовано

Для uniform duplex-заказа появилась отдельная plan-family:

```text
workAndTurnDedicatedPairs
```

Каждая реальная печатная пара получает:

- одну симметричную общую форму;
- горизонтальный переворот листа;
- два печатных прогона;
- готовые лицо и оборот, независимо проверенные прежним duplex-валидатором;
- собственные метрики бумаги, форм, пластин, прогонов, перетиража и стоимости.

План участвует в том же lossless-каталоге, что и:

- `paperMinimum`;
- `dedicatedPairForms`.

Рекомендация может перейти на свой оборот при приоритете стоимости или количества форм. Явный выбор оператора сохраняется отдельно от рекомендации.

## 2. Условия применимости

Plan-family строится только когда одновременно выполняются условия:

1. заказ двусторонний;
2. цветность лица и оборота больше нуля;
3. каждая страница лица имеет реальную оборотную пару;
4. uniform-сетка содержит чётное число колонок;
5. используется поддержанный горизонтальный переворот;
6. все включённые строки текущего uniform-пайплайна имеют одинаковые формат, цветность, выпуск, рез и duplex preference.

Нечётное число страниц создаёт технически пустую оборотную страницу. В таком заказе:

- режим `Автоматически` оставляет только обычные раздельные планы;
- принудительный `Свой оборот` блокируется понятной ошибкой;
- фиктивная общая форма для пустой оборотной страницы не создаётся.

Сетка с нечётным числом колонок не блокирует весь заказ: для неё остаются обычные раздельные plan-family. Свой оборот появляется только на подходящих ориентациях.

## 3. Выбор оператора

Поле `print.duplexPreference` теперь действительно управляет каталогом:

| Значение | Поведение |
|---|---|
| `auto` | сравниваются раздельные планы и допустимый свой оборот |
| `separateFrontBackForms` | свой оборот исключается |
| `workAndTurn` | остаются только допустимые планы общей формы |

Если принудительный `workAndTurn` невозможен, расчёт возвращает blocking issue вместо молчаливого перехода на чужой оборот.

## 4. Формы, пластины и прогоны

Для общей формы:

```text
layoutForms = число shared plates
pressPasses = physicalSheets × 2
```

Текущая модель хранит только количество красок, без идентификаторов красочных каналов. Поэтому количество пластин общей формы считается так:

```text
colorPlates = layoutForms × max(frontColors, backColors)
```

Следствия:

- `4+1` → 4 пластины на общую форму;
- `1+4` → 4 пластины на общую форму;
- `4+4` → 4 пластины на общую форму.

Это честное допущение текущей count-only модели. Когда проект начнёт хранить реальные наборы красок или spot-color identifiers, правило потребуется расширить до объединения фактических каналов.

## 5. Схема и PDF

В рабочем интерфейсе выбранный свой оборот показывает:

1. `Общая форма` — фактическая shared plate;
2. `Лицо` — контроль готового изделия;
3. `Оборот` — зеркальный контроль готового изделия;
4. `Вместе` — лицо и оборот рядом.

PDF схем для `workAndTurn` содержит **одну страницу общей формы на монтаж**, а не две фиктивные страницы лица и оборота. Страница помечается как:

- одна общая форма;
- горизонтальный переворот;
- два прогона.

Производственный отчёт сохраняет:

- одну layout-форму;
- ноль отдельных back forms;
- два прогона на физический лист.

## 6. Что не заявлено

Текущая реализация не является глобальным поиском всех способов своего оборота. В scope не входят:

- произвольные mixed work-and-turn монтажи;
- смешение разных форматов в одной общей форме;
- вертикальный переворот;
- автоматическое объединение нескольких разных печатных пар на одной shared plate;
- оптимизация по реальным именам CMYK/spot-каналов;
- simplex и технически пустые обороты внутри общей формы;
- доказательство глобального оптимума за пределами заявленной конечной family.

Каталог полный только внутри явно заявленной области:

```text
fitting uniform 0°/90° grids
× supported separate plan families
× horizontally eligible dedicated-pair work-and-turn family
```

## 7. Проверки

Обязательные проверки ветки:

- work-and-turn появляется только на сетках с чётным числом колонок;
- `auto`, `separateFrontBackForms`, `workAndTurn` реально фильтруют планы;
- нечётные страницы блокируют принудительный свой оборот;
- каждый материализованный план production-ready и не имеет недопечатки;
- `4+1` и `1+4` дают одинаковое корректное число пластин;
- сравнение стоимости показывает реальную экономию против отдельной dedicated family;
- selected-plan export создаёт одну shared-plate PDF page на монтаж;
- Chromium видит режим `Общая форма` и скачивает одностраничный PDF;
- существующие separate-front/back, mobile, overflow и PDF regression остаются зелёными.
