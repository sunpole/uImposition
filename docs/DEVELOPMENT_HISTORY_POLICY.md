# Политика истории разработки / Development History Policy

## Основное правило

Полезные материалы, созданные во время разработки uImposition, сохраняются в GitHub как история проекта.

К таким материалам относятся:

- milestone-планы и промежуточные архитектурные документы;
- release evidence и provenance;
- длинные технические Chromium-скриншоты;
- короткие Telegram/uNews-скриншоты;
- проверочные PDF и их render-artifacts;
- workflow, diagnostic logs и тестовые сценарии;
- regression fixtures;
- старые, но корректные описания завершённых этапов;
- решения, которые не вошли в текущий интерфейс, но могут пригодиться позднее.

Материал не удаляется только потому, что он перестал быть главным или стал историческим.

## Что действительно удаляется

Удаление допустимо, если файл:

1. содержит заведомо неверные производственные формулы;
2. показывает ложный или несуществующий результат;
3. содержит секреты, приватные данные или небезопасную информацию;
4. повреждён и не может служить доказательством или историей;
5. полностью дублирует другой файл без дополнительной исторической ценности;
6. способен ввести следующего разработчика в заблуждение и не может быть исправлен пометкой статуса.

По возможности неверный исторический материал не удаляется молча: причина удаления фиксируется в commit или Pull Request.

## Текущий период alpha

Во время alpha-разработки:

- исторические документы остаются в основной истории Git;
- evidence-файлы и screenshots можно хранить в проекте;
- длинные технические снимки используются для проверки;
- для Telegram предпочтителен отдельный крупный снимок только новой функции;
- старый корректный artifact не заменяется новым задним числом;
- новая версия получает свой собственный screenshot и provenance.

## Будущая архивация

При переходе из alpha в beta или после завершения крупного цикла владелец проекта отдельно решит, куда переместить исторические материалы:

- архивная ветка;
- отдельный каталог;
- отдельный архивный репозиторий;
- сохранение в текущем репозитории с индексом.

До такого решения агент не должен самостоятельно массово удалять или переносить историю.

## Источники истины и статус

Исторический файл не обязан описывать текущее состояние. Текущими источниками истины остаются:

- `START_HERE.md`;
- `docs/CURRENT_STATE.md`;
- `VERSION.json`, `VERSION.md`, `CHANGELOG.md`;
- актуальный milestone-план;
- код, тесты, Pull Request и GitHub Actions.

Исторические документы должны сохранять дату, milestone или явную пометку состояния, чтобы их нельзя было спутать с текущей инструкцией.

---

## English summary

Useful development artifacts remain in GitHub as project history. Do not delete plans, evidence, screenshots, PDF artifacts, workflows, tests, fixtures, or old but correct milestone documents merely because they are no longer current. Delete only material that is false, unsafe, corrupted, misleading beyond repair, or valueless duplication. Any large archive move is a future owner decision for the alpha-to-beta transition or another major project boundary.
