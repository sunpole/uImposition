# M7.5 — редактор приоритетов оператора

Дата: 2026-07-27.

## Цель

Один и тот же допустимый производственный каталог может иметь разные правильные рекомендации в зависимости от текущей цели оператора:

- меньше бумаги;
- ниже производственная себестоимость;
- меньше layout-форм;
- меньше цветовых пластин;
- меньше листопрогонов;
- меньше перетиража;
- меньше дробления заказов;
- более компактные формы;
- больше разных заказов на одном монтаже.

Редактор меняет только порядок целей и повторно ранжирует уже готовые варианты. Geometry, layouts, production reports и pricing metrics не строятся заново.

## Лексикографический порядок

Цели применяются последовательно.

Первая цель, по которой два решения отличаются, определяет более высокий ранг. Следующие цели используются только при равенстве предыдущих.

Это не скрытая сумма коэффициентов и не непрозрачный score.

## Активные цели

Редактор получает текущий список из lossless-каталога.

При готовом прайсе доступны все `11` целей:

1. физические листы;
2. расчётная стоимость;
3. layout-формы;
4. цветовые пластины;
5. перетираж файлов;
6. перетираж печатных пар;
7. листопрогоны;
8. разделённые заказы;
9. число монтажей;
10. компактность раскладки;
11. разные заказы на одном монтаже.

Без рабочего прайса денежная цель временно отсутствует. Остальные варианты и цели продолжают работать.

## Быстрые режимы

- `По умолчанию` — бумага, стоимость, формы и остальные стандартные цели;
- `Бумага` — физические листы первыми;
- `Стоимость` — себестоимость первой; доступно только при готовом прайсе;
- `Формы` — layout-формы, пластины и число монтажей первыми;
- `Прогоны` — листопрогоны и бумага первыми;
- `Перетираж` — перетираж файлов и пар первыми.

После выбора режима отображается фактический полный порядок. Его можно продолжить менять вручную.

## Управление

### Desktop

- drag-and-drop строк;
- кнопки `↑ / ↓` как доступная альтернатива;
- видимая позиция каждой цели;
- подпись `меньше лучше` или `больше лучше`.

### Mobile

- drag-and-drop не обязателен;
- каждая строка имеет крупные кнопки `↑ / ↓`;
- быстрые режимы располагаются в две колонки;
- список остаётся внутри компактной панели настроек.

## Жёсткие ограничения

Отдельный read-only блок показывает ограничения, которые нельзя перемещать:

- нулевая недопечатка;
- корректная печатная область;
- правильные пары лицо/оборот;
- корректная ориентация;
- допустимый способ оборота;
- проверенный production report.

Оператор может менять приоритеты только среди допустимых решений. Редактор не может разрешить недопечатку или повреждённую схему.

## Гарантия без регенерации

`rerankUserProductionPlanSet` создаёт новый catalog wrapper вокруг тех же plan-объектов.

Проверяемые свойства:

- `next.plans === previous.plans`;
- каждый plan сохраняет object identity;
- `regeneratedPlanCount === 0`;
- impositions и reports не меняются;
- меняются только rank, recommendation, Pareto/dominated annotations и objective order.

## Явный выбор оператора

Recommendation и selected plan — разные состояния.

Пример:

1. оператор явно выбирает paper-focused план;
2. переключает цель на `Стоимость`;
3. dedicated-план становится рекомендованным;
4. выбранным остаётся paper-focused план;
5. схемы и PDF продолжают относиться к явному выбору оператора.

Программа не должна молча заменить выбранный вариант новой рекомендацией.

## Сохранение предпочтения

Порядок целей хранится отдельно от текущего временного plan set.

Он сохраняется при изменении:

- тиражей;
- размеров;
- цветности;
- прайса;
- состава доступных планов.

Если прайс очищен, `estimatedTotalCost` временно исключается из активного списка. После восстановления прайса она возвращается на сохранённую позицию.

Если пользователь ещё не менял порядок и сначала считал без прайса, при первом вводе цены денежная цель появляется на стандартном втором месте.

Кнопка `По умолчанию` возвращает стандартную иерархию, не очищая заказ, прайс или выбранный вариант.

## Публичное состояние

Sanitized runtime event может показывать:

- текущий objective order;
- recommended plan ID;
- число повторно использованных планов;
- число заново построенных планов;
- selected plan summary.

Raw layouts, reports и внутренние кандидаты не публикуются.

## Контрольный результат

Для заказа из трёх двухстраничных A6 по `100`, цветности `4+1` и evidence-прайса:

- paper-first рекомендует `uniform-r90-paper-minimum` — `20` листов;
- cost-first рекомендует `uniform-r90-dedicated-pairs` — `21` лист, но меньше форм и стоимость `240,05 BYN`;
- оба находятся на Pareto-frontier;
- все четыре допустимых плана остаются в каталоге;
- изменение цели использует `4` готовых плана и строит заново `0`.

## Граница

Редактор меняет выбор среди уже найденных вариантов. Он не расширяет сам search space.

Отдельные будущие задачи:

- дополнительные uniform plan-family;
- bounded search разных последовательностей форм;
- user-driven work-and-turn;
- mixed-format и mixed-rotation;
- индивидуальные параметры строк;
- модель выручки и прибыльности.
